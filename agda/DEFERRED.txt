# THE LEAF-ONLY RULE (Anthony, 2026-08-15) — WHY THE LIST IS FROZEN.
# Passed-only is NOT "normal while the parent is a postulate".  It is the
# state the rule exists to prevent, because such a lemma has never had its
# FIT tested: nothing reduces it, so nothing checks that its type is the one
# the parent actually needs.  Two `-core` discharges (opIterD-budget,
# init-capsOK?-base) each shed seven-plus leading hypotheses for exactly
# that reason — ingredients claimed, never actually ingredients, undetected
# until someone wrote the real proof.
#
# So a postulate must be a LEAF.  Write an assembly as a REAL BODY over
# POSTULATED LEAVES — `postulate l : L` and `P = <body applying l>`, where
# the composition is CHECKED — never as a postulate over proven pieces
# (`P = P-core l …`), where the composition is asserted and checked by
# nobody.  When the body cannot be written yet, postulate the parent BARE
# and mint no leaves; an unwritten route belongs in a header comment, not
# in a type that verifies nothing.  Nothing is ever blocked by this: the
# bare postulate is always available, so the ordering merely becomes
# assembly-first, leaves-second — which is what outside-in already demands.
#
